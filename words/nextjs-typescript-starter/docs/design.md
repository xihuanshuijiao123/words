## 1. 总体架构

```
┌────────────────────────────── 客户端 ──────────────────────────────┐
│   移动端 H5 (Next.js App Router)                                    │
│   ├─ (main) 布局: 底部 Tab(首页 / 我的)                              │
│   ├─ 首页            /            : 最近学习 + 全部单词书            │
│   ├─ 我的            /profile     : 用户信息 / 进度 / 退出           │
│   ├─ 学习页          /learn/[bookId]   : 单词卡片                    │
│   ├─ 单词详情        /word/[bookId]/[wordId] : 完整词条              │
│   └─ API Route Handlers (BFF)                                       │
│        /api/auth/*     认证        /api/books/*    单词书             │
│        /api/study/*    学习进度    /api/words/*    单词               │
└────────────────────────────────────────────────────────────────────┘
                              │
                              │ Drizzle ORM (node-postgres)
                              ▼
        ┌──────────────────────── PostgreSQL (Supabase) ───────────────┐
        │  admin-users  admin-session  books  words                     │
        │  study_progress (新增)  word_records (新增)                    │
        └──────────────────────────────────────────────────────────────┘
```

- H5 应用与后台（`words-admin`）**共享同一套 PostgreSQL 数据**。
- 认证采用与后台一致的 **Cookie 会话方案**（`admin_session_token`，HttpOnly，7 天）。
- H5 通过自身的 API Route Handlers 直连数据库，作为 BFF 层，保证前端页面简洁。
- 若希望 H5 复用后台已部署的认证/单词书接口，也可通过 `NEXT_PUBLIC_API_BASE` 反向代理到 `words-admin`，本文默认采用「H5 自实现、共享数据库」方式。

## 2. 数据库设计

### 2.1 现有表（不可改动其结构）

以下为已在 Supabase 中存在的表，H5 只读 `books` / `words`，复用 `admin-users` / `admin-session`。

**`public.words` — 单词数据表**

```sql
create table public.words (
  id bigint generated by default as identity not null,
  "wordRank" integer null,
  "headWord" text null,
  content json null,
  "bookId" text null,
  constraint words_pkey primary key (id)
) TABLESPACE pg_default;
```

> `content` 为完整词条 JSON，结构见 [§2.4](#24-wordcontent-json-结构)。

**`public.books` — 单词书数据表**

```sql
create table public.books (
  id uuid not null default gen_random_uuid (),
  title text not null,
  word_count integer not null default 0,
  cover_url text null,
  book_id text not null,
  tags text null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint books_pkey primary key (id),
  constraint books_book_id_unique unique (book_id)
) TABLESPACE pg_default;
```

**`public.admin-users` / `public.admin-session` — 用户与会话表（已存在）**

```sql
create type public.user_role as enum ('system', 'admin');
create table public.admin-users (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  email text not null unique,
  password_hash text not null,
  role public.user_role default 'admin' not null,
  created_at timestamptz default now() not null
);
create table public.admin-session (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.admin-users(id) on delete cascade,
  token text not null unique,
  expires_at timestamptz not null,
  created_at timestamptz default now() not null
);
```

> 表间关系：`words.bookId`（逻辑）↔ `books.book_id`（业务主键）；`admin-session.user_id` → `admin-users.id`（FK）。注意 `words` 表列名为驼峰（`bookId`），`books` 表列为下划线（`book_id`），映射时需区分。

### 2.2 新增表：用户学习进度

结合「背单词」的两种粒度（**书级进度** 与 **词级掌握**），新增两类表：

#### 表 A：`study_progress` — 书级学习进度（用于「最近学习」与「我的」总进度）

```sql
create table public.study_progress (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.admin-users(id) on delete cascade,
  book_id text not null,                      -- 关联 books.book_id
  word_id text not null,                      -- 最近学到的词 content.word.wordId
  last_rank integer not null default 0,       -- 最近学到的 wordRank(0 = 尚未开始)
  done_count integer not null default 0,      -- 已学(见)过的词数
  status text not null default 'in_progress', -- in_progress | completed
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint study_progress_user_book_unique unique (user_id, book_id)
) TABLESPACE pg_default;

create index study_progress_user_updated_idx
  on public.study_progress (user_id, updated_at desc);
```

- 唯一约束 `(user_id, book_id)`：每个用户每本书只有一条进度记录。
- **「最近学习」**：按 `user_id + updated_at desc` 取第一条。
- `last_rank` 是续学的锚点，下一页从 `last_rank + 1` 开始。

#### 表 B：`word_records` — 词级掌握状态（用于按词统计与后续复习算法）

```sql
create table public.word_records (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.admin-users(id) on delete cascade,
  book_id text not null,                      -- 关联 books.book_id
  word_id text not null,                      -- content.word.wordId
  rank integer not null,                      -- wordRank 快照, 便于排序
  mastery text not null default 'new',        -- new(未学) | learning(学习中) | mastered(已掌握)
  review_count integer not null default 0,    -- 复习次数
  last_review_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint word_records_user_word_unique unique (user_id, word_id)
) TABLESPACE pg_default;

create index word_records_user_book_idx
  on public.word_records (user_id, book_id);
```

- 唯一约束 `(user_id, word_id)`：同一用户同一词只有一条记录（`wordId` 形如 `PEPXiaoXue3_1_1`，在一本书内唯一）。
- `done_count` 可由 `word_records` 派生（`count(*) where mastery in ('learning','mastered')`），作为书级进度的冗余字段以加速查询。

### 2.3 实体关系（ER）图

```
admin-users (1) ───< admin-session (N)
      │
      │ 1
      ├────────< study_progress (N)    ...  user_id, book_id(→books.book_id)
      │
      └────────< word_records   (N)    ...  user_id, word_id

books (1, 业务主键 book_id) ───< words (N)     ...  words.bookId = books.book_id
books (1, book_id) ───< study_progress (N)
books (1, book_id) ───< word_records (N)
```

### 2.4 `word.content` JSON 结构

`words.content` 是单行 JSON，含完整词条，前端按如下路径取值：

```ts
type WordContent = {
  word?: {
    wordHead: string;
    wordId: string; // 例如 "PEPXiaoXue3_1_1"
    content: {
      sentence?: {
        sentences?: { sContent: string; sCn: string }[];
        desc?: string;
      };
      usphone?: string; // 美音音标
      ukphone?: string; // 英音音标
      ukspeech?: string; // 英音发音参数 "ruler&type=1"
      usspeech?: string; // 美音发音参数 "ruler&type=2"
      trans?: {
        tranCn?: string;
        descCn?: string;
        descOther?: string;
        tranOther?: string;
      }[];
      phrase?: { phrases?: { pContent: string; pCn: string }[]; desc?: string };
      syno?: {
        synos?: { pos: string; tran: string; hwds?: { w: string }[] }[];
        desc?: string;
      };
      relWord?: {
        rels?: { pos: string; words?: { hwd: string; tran: string }[] }[];
        desc?: string;
      };
      remMethod?: { val: string; desc?: string };
    };
  };
};
```

发音地址拼装：

```
英音: https://dict.youdao.com/dictvoice?audio=${ukspeech}   // audio=ruler&type=1
美音: https://dict.youdao.com/dictvoice?audio=${usspeech}   // audio=ruler&type=2
```

### 2.5 迁移（Drizzle）

在 H5 项目中加入与 `words-admin` 一致的 Drizzle 配置，新增迁移文件记录 `study_progress` 与 `word_records` 两张表。对应 Drizzle schema：

```ts
// lib/db/schema.ts
export const studyProgress = pgTable(
  "study_progress",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    userId: uuid("user_id")
      .notNull()
      .references(() => adminUsers.id, { onDelete: "cascade" }),
    bookId: text("book_id").notNull(),
    wordId: text("word_id").notNull(),
    lastRank: integer("last_rank").notNull().default(0),
    doneCount: integer("done_count").notNull().default(0),
    status: text("status").notNull().default("in_progress"), // in_progress | completed
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [unique("study_progress_user_book_unique").on(t.userId, t.bookId)],
);

export const wordRecords = pgTable(
  "word_records",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    userId: uuid("user_id")
      .notNull()
      .references(() => adminUsers.id, { onDelete: "cascade" }),
    bookId: text("book_id").notNull(),
    wordId: text("word_id").notNull(),
    rank: integer("rank").notNull(),
    mastery: text("mastery").notNull().default("new"), // new | learning | mastered
    reviewCount: integer("review_count").notNull().default(0),
    lastReviewAt: timestamp("last_review_at", { withTimezone: true }),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (t) => [unique("word_records_user_word_unique").on(t.userId, t.wordId)],
);
```

## 3. 后端 API 设计

H5 的 API 路由与后台接口风格一致：`JSON` 入参/出参，未登录返回 `401`，错误返回 `{ error: string }`。

### 3.1 接口总览

| 方法 | 路径                        | 说明                                 | 是否需要登录 |
| ---- | --------------------------- | ------------------------------------ | ------------ |
| GET  | `/api/auth/me`              | 当前用户 + 是否已有管理员            | 否           |
| POST | `/api/auth/signin`          | 邮箱密码登录                         | 否           |
| POST | `/api/auth/signup`          | 注册（首个用户为 system）            | 否           |
| POST | `/api/auth/logout`          | 退出登录                             | 是           |
| GET  | `/api/books`                | 全部单词书                           | 否           |
| GET  | `/api/books/[bookId]/words` | 某书全部词条（按 `wordRank` 升序）   | 否           |
| GET  | `/api/words/[wordId]`       | 单词详情（按 `content→wordId` 定位） | 否           |
| GET  | `/api/study`                | 学习总览（最近学习 + 我的进度列表）  | 是           |
| GET  | `/api/study/[bookId]`       | 某书进度（用于续学锚点）             | 是           |
| PUT  | `/api/study/[bookId]`       | 上报学习进度（更新进度与词级状态）   | 是           |

> 认证相关接口在 H5 内复刻 `words-admin` 的逻辑（session.ts / password.ts / schema），保证与后台共用 `admin-users`、`admin-session` 表。

### 3.2 认证接口（复刻后台逻辑）

- `POST /api/auth/signup`：`{ name, email, password }` → `{ ok }` 或 `{ error }`。邮箱唯一校验；密码 ≥ 6 位。
- `POST /api/auth/signin`：`{ email, password }` → `{ ok, user: { id, name, email, role } }` 或 `{ error }`。
- `POST /api/auth/logout`：清空 Cookie 与会话。
- `GET /api/auth/me`：`{ user, hasAdmin }`，`user` 可为 `null`。

### 3.3 单词书与单词接口

**GET `/api/books`**（复用后台实现，无需登录）

```json
{
  "books": [
    {
      "id": "…",
      "title": "…",
      "wordCount": 20,
      "coverUrl": null,
      "bookId": "PEPXiaoXue3_1",
      "tags": "K12,人教版",
      "createdAt": "…",
      "updatedAt": "…"
    }
  ]
}
```

**GET `/api/books/[bookId]/words`**（按 `bookId` 查 `words`，`ORDER BY "wordRank" ASC`）

```json
{ "words": [ { "id": 1, "wordRank": 1, "headWord": "ruler", "bookId": "PEPXiaoXue3_1", "content": { … } } ] }
```

**GET `/api/words/[wordId]`**

```sql
select * from public.words
where "bookId" = $1
  and content #>> '{word,wordId}' = $2
limit 1;
```

### 3.4 学习进度接口

**GET `/api/study`** — 响应：

```json
{
  "recent": {
    "bookId": "PEPXiaoXue3_1",
    "title": "人教版三年级上",
    "coverUrl": null,
    "total": 20,
    "done": 3,
    "percent": 15,
    "lastRank": 3,
    "nextRank": 4,
    "status": "in_progress",
    "updatedAt": "…"
  } | null,
  "progressList": [ /* 每本已学书同样结构，按更新时间降序 */ ]
}
```

**GET `/api/study/[bookId]`** — 返回该书的进度，用于学习页初始化：

```json
{ "exists": true, "lastRank": 3, "done": 3, "total": 20, "nextRank": 4, "status": "in_progress" }
{ "exists": false }   // 尚未学习，应从第 1 个词开始
```

**PUT `/api/study/[bookId]`** — 前端在切到下一个词时上报：

```ts
// 请求体
{
  wordId: string; // 当前词的 content.word.wordId
  wordRank: number; // 当前词 rank
  mastery: "learning" | "mastered"; // 本次状态
}
```

服务端逻辑（事务）：

1. `upsert word_records`（按 `user_id + word_id`）：设置 `rank`、`mastery`，`review_count + 1`（非首次），`last_review_at = now()`。
2. `upsert study_progress`（按 `user_id + book_id`）：`word_id = 当前词`，`last_rank = wordRank`，`done_count = count(word_records 中 mastery in ('learning','mastered'))`，`status = (wordRank >= 该书 wordCount ? 'completed' : 'in_progress')`，`updated_at = now()`。
3. 由于单参数即可定位，推荐使用 `onConflict` upsert。

### 4.4 状态管理

- 认证状态：沿用后台的 `AuthProvider`（[auth-provider.tsx](file:///d:/github_project3/words/words-admin/components/auth/auth-provider.tsx)），提供 `user / hasAdmin / isReady / signin / signup / signout`。H5 项目内复刻该 Context。
- 页面级数据：使用 SWR / React Query 负责拉取：`/api/books`、`/api/books/[bookId]/words`、`/api/study` 等；亦可用原生 `fetch` + `useEffect`（与后台一致）。
- 学习页内部状态：`index`（当前词下标），由 `words` 列表与 `study[bookId].nextRank` 计算初始 `index`。

### 4.5 首页逻辑

```tsx
const { user, isReady } = useAuth();
const { data: books } = useBooks();
// 已登录才请求 /api/study；未登录则只显示单词书
const { data: study } = useStudy({ enabled: !!user && isReady });

const recent = study?.recent; // null 时不展示「最近学习」模块
```

- 已登录且有 `recent`：顶部渲染 `RecentStudy`；下方渲染全部 `BookCard`。
- 已登录但无 `recent`：不渲染「最近学习」模块。
- 未登录：只渲染全部 `BookCard`。点击卡片 → 跳 `/profile` 并触发登录弹窗。

### 4.6 学习页（单词卡片）

- 加载 `words` 列表；计算起始下标：

```ts
const nextRank = study?.nextRank ?? 1; // 无进度则从 1 开始
const startIdx = Math.max(0, nextRank - 1);
const [index, setIndex] = useState(startIdx);
const card = words[index];
```

- 卡片渲染（仅取少量字段，见需求 §5.3）：`headWord`、`usphone`、发音按钮、`trans[0].tranCn`、`sentence.sentences[0]`。
- 「下一个」→ `setIndex(i => i + 1)`，并调用 `PUT /api/study/[bookId]` 上报当前词掌握状态；到最后一词时按钮置灰或提示「已学完」。
- 点击卡片或「查看详情」→ 跳 `/word/[bookId]/[card.content.word.wordId]`。

### 4.7 单词详情页

- 路由入参 `bookId` + `wordId`，调用 `GET /api/words/[wordId]`（或直接从已缓存列表取）渲染完整字段（需求 §5.4）：
  - 发音按钮（美/英）
  - `trans[].tranCn` / `tranOther`
  - `sentence.sentences[]`（全部）
  - `phrase.phrases[]`
  - `syno.synos[]`（`pos` + `tran` + `hwds[].w`）
  - `relWord.rels[]`（`pos` + `words[].hwd` + `tran`）
  - `remMethod.val`

### 4.8 我的与登录/注册弹窗

- **未登录**：`AuthDialog` 为 `Dialog`（shadcn/ui），默认「登录」模式，可切「注册」；校验规则复用后台：
  - 邮箱：`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
  - 密码 ≥ 6 位；注册两次密码一致。
- **已登录**：展示 `user.email`、学习进度列表（`study.progressList` 渲染为 `ProgressBar` + 书名 + 进度）、退出登录按钮（调用 `signout` → 回首页）。
- 触发链路：未登录点单词书 → `router.push("/profile")` + 打开弹窗；登录成功后若来自单词书点击，继续 `router.push("/learn/[bookId]")`。

## 5. 关键业务流程与业务规则

### 5.1 首次进入 / 续学

```
进入 /learn/[bookId]
  → GET /api/study/[bookId]
    ├─ { exists: false } → startIdx = 0（第 1 个词）
    └─ { exists: true }  → startIdx = nextRank - 1（上次学到的下一个词）
  → 加载 GET /api/books/[bookId]/words（按 wordRank 升序）
  → index 越界保护（列表空 → 空态；nextRank 超界 → startIdx = 0 重学）
```

### 5.2 进度上报

- 每次切到新词（或离开当前词前）调用 `PUT /api/study/[bookId]`。
- 服务端事务同时更新 `word_records`（词级）与 `study_progress`（书级）。
- `done_count` 恒等于该书已学词数，用于「最近学习」与「我的」进度条。

### 5.3 「最近学习」定义

- 对当前用户，取 `study_progress` 中 `updated_at` 最新一条（按索引 `study_progress_user_updated_idx`）。
- 仅有进度记录时才返回；无记录返回 `recent: null`。

### 5.4 学到最后一词

- `wordRank >= book.wordCount` 时：`study_progress.status = 'completed'`，学习页「下一个」按钮置灰并提示「已学完」。

## 7. 安全与边界处理

| 方面       | 处理                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------- |
| 会话安全   | `admin_session_token` 设 `HttpOnly` + `SameSite=Lax`；生产 `Secure`；7 天过期，过期自动清理 |
| 密码       | 使用与后台一致的 `bcrypt` 哈希（`lib/password.ts`），不下发 `passwordHash`                  |
| 越权       | 所有 `/api/study/*` 均需登录，且以 `getSessionUser().id` 写入 `user_id`，不允许前端指定     |
| 输入校验   | 登录/注册/进度上报均做字段与类型校验（邮箱正则、密码 ≥ 6 位、wordRank 为正整数）            |
| 数据库字段 | `wordId` 以 `content->'word'->>'wordId'` 为准，防止前端伪造导致关联错位                     |
| 空态/异常  | 列表空态、进度不存在（`exists:false`）、网络异常重试、索引越界保护                          |

## 8. 技术要点与约定

1. **发音**：`https://dict.youdao.com/dictvoice?audio=${ukspeech|usspeech}` 直接 `new Audio(url).play()`。
2. **数据结构差异**：`words` 列名为驼峰、`books` 为下划线；在 Drizzle 中分别以 `"wordRank"`、`bookId` 与 `word_count`、`book_id` 映射，查询务必区分。
3. **`wordId` 关联**：详情页按 `content #>> '{word,wordId}'` 查询；学习页直接使用已加载列表的下标，避免额外请求。
4. **`content` 为 `json` 非 `jsonb`**：使用 `#>>` 取值；如需按词高效定位，可考虑为 `books.book_id`、`words."bookId"`、`words.content` 建立索引。
5. **续学锚点**：以 `study_progress.last_rank + 1` 作为起点，并用 `clone`/`startIdx` 下标保护防超界。
6. **复用策略**：H5 与后台共享数据库和认证方案，认证/书查询逻辑可平移自 `words-admin`，减少重复设计。
